# Reproducibility

## Engineering reproduction: no provider account or cost

Follow the source installation in README.md on macOS arm64 or Ubuntu24.04 x86_64 with Python3.12 and the required OS sandbox. Install requirements-tested.txt in a new virtual environment, install this package, and run pip check and tools/check_install.py.

```sh
python scripts/check_release.py
python scripts/check_secrets.py --all-files
python tests/isolation.py --output ./acceptance-isolation-reproduction
python tests/acceptance.py --output ./acceptance-reproduction
```

The test launches a loopback HTTP server and supplies deterministic native tool messages. Actual LangGraph nodes, databases, model-protocol journals, the OS sandbox and filesystem outputs execute. The expected output is 17 passed checks, 45 fixture HTTP requests and zero external provider calls. It covers two hypothesis/test/assessment stages, independent tools, report archives, pause/reopen, illegal submissions, read-only SQL, missing measurement services, error recovery and secret redaction.

The fixture is intentionally an engineering test. Its positive sample claim is not a discovered commercial mechanism. A critic agreeing in the fixture is not evidence of a general critic advantage.

The public synthetic example is generated by examples/create_example_data.py with seed20261104. It creates four sites ×30 dates, 120 rows and explicit definitions. The generator is visible; it is not a held-out mechanism benchmark. Do not report deployment-example success as blind discovery.

## Optional real-model study

Real runs are opt-in and incur provider costs. Use your own compatible model endpoint and credential. The repository contains neither an account key nor original private research workspaces.

Before a run record the Git commit, interpreter/dependency versions, lawful input hashes, model/backend identity, generation parameters, initial state, all-role capacity and request limit, persistent deadline, stage count, and stopping criteria. Keep thinking/high/max65536 when reproducing this protocol. Do not compare modes that silently differ in model or tools.

Create a new workspace using the documented CLI. Preserve the whole workspace after the run, including all rejected operations, counterevidence, revisions, failed/unknown requests and consumed resources. Pauses or continuations do not create new independent samples. Do not reset limits by recreating the same case.

For research quality, inspect each final claim against the original hypothesis/prediction, object, denominator, measurement definition, scope and actual evidence. Check competing explanations, whether a response caused a real revision, and whether a report still uses a corrected error. Distinguish arithmetic replication, observational association and causal identification.

Record all roles' reported tokens, unknown reservations, requests, tool calls, wall time and measurement costs where relevant. Critic agreement, tool success, issue count and report existence are not correctness scores. Report honest unresolved and negative outcomes.

## What this repository reproduces

It reproduces the local engineering path and transparent data-format example. It does not provide a paper-level comparative benchmark, a live-provider deterministic replay, a proprietary business dataset, or proof of long-term improvement. See [evaluation scope](EVALUATION.md). No paper/DOI has been attached to this initial code release.
