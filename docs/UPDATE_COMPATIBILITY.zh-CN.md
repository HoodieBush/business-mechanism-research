# Agent更新适配验收

每次更新提示、工具、输出、工作流、传输、迁移或版本，都要验收完整运行契约。单个函数回归通过、工具能调用或进程有心跳，不能替代此项。检查运行在Python3.12，禁止外部模型推理。

```bash
python -m pip install --no-deps .
python tests/update_compatibility.py --output /tmp/business-update-check
```

输出目录必须尚不存在。失败输出保留，修复后使用新目录；不覆盖失败记录。CI必须执行此检查并保存`result.json`及`contract-manifest.json`。

|适配面|检查|错误反例/失败出口|
|---|---|---|
|源代码→实际安装包|全部公开Python源哈希匹配|旧安装环境不能通过新代码验收|
|提示与示例→工具schema|两角色全部函数示例解析并严格验证；完整一致意见必须有真实计算覆盖示例|遗漏复核示例、旧字段或仅读取却声称数值核验会失败|
|注册表→模型实际schema|函数名唯一且可执行；参数和描述均来自当前注册表|缓存旧描述或旧schema被反例拦住|
|契约→说明与任务视图|当前required components都有说明，context和agenda的workflow_phase一致|只改上下文未改权威查询入口会失败|
|计算结果→目录→校验器|真实SQL、JSON、纯文本回执的所有展示路径能解析到原值；虚构路径拒绝|源码/元数据不替代计算；文本只允许逐字整行eq，不猜数字|
|局部额度→上下文→工具集合|审查片段上限一致，收尾阶段的实际tools过滤生效|描述上限和实际允许工具不一致会失败|
|实际已付费请求→执行|从不可变原请求取得工具集合；混入未提供工具则整批零执行，下一合法调用只执行一次|不能只隐藏工具而仍接受调用；保留原响应及费用|
|预检→草稿→CAS修补→提交|独立回归覆盖原稿保留、字段修补、精确commit参数和有效核验；业务验收覆盖正式交付|格式有效不能冒充科学正确；不自动删除意见|
|迁移→活动缓存与历史|两角色活动系统提示/工具schema更新；原记录、付费账本及截止保持，旧有效证明按当前校验器重放|旧科学文本和已付费请求不改写，不清空费用|
|候选副本→实际部署|对真实前序冻结包、真实源项目和迁移副本执行同样的逐项核对|只拿当前版本复制夹具代替真实升级验证不合格|

后续新增工具或示例会自动进入枚举检查，不维护“只检查某两个示例”的白名单。负例必须保留，证明检查确实能阻止旧描述、旧schema和旧正面示例，而非所有输入都通过。

真实部署先停止前序控制器并排空付费批次，使用显式迁移副本；在新授权窗口及模型请求开始前，运行：

```bash
python tests/update_compatibility.py \
  --output /tmp/business-deployment-check \
  --upgrade-project /absolute/path/to/migrated-project \
  --baseline-project /absolute/path/to/paused-predecessor \
  --baseline-package /absolute/path/to/frozen/site-packages/business_mechanism
```

必须用新冻结环境的Python运行。记录活动提示/工具schema指纹、包源身份、迁移回执和原费用位置，然后才启动独立实验。若核验失效，先检查具体旧证明与新契约；不能静默清除后直接部署。

科学支持/反驳、已审查的未决披露、执行交接、进程持续性分别计数。此验收证明已列出的接口与升级路径相容；真实模型的研究质量及持续运行时长仍另行观察。Linux与macOS的隔离检查也必须独立执行，不能由本检查替代。
